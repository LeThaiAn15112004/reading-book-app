# iOS readiness (T079)

**Date**: 2026-11-05 | **Scope**: every script and every piece of Mobile code added by spec 008, reviewed against
"macOS and iOS Compatibility Rules" in [plan.md](./plan.md). Nothing here has been built or run on iOS or macOS:
that is M6, a separate task (OD-11). This file lists what follows the rules by reading the code, and what stays
unproven until M6.

## Review against the rules

| Rule (plan.md) | Result | Evidence |
|---|---|---|
| Scripts are Node `.mjs` or npm commands; no PowerShell, `cmd` or Windows paths | **Pass** | `source/scripts/check-desktop-baseline.mjs`, `source/scripts/boundaries/*.mjs`, `reading-book-mobile/scripts/*.mjs`: Node only, `path.join` / `path.resolve`; backslashes appear only in `.replaceAll('\\', '/')` normalisation. `check-desktop-baseline.mjs` runs `git` without a shell on purpose. `link-expo-root.mjs` makes a junction on Windows and an ordinary symlink elsewhere |
| Config plugins portable | **Pass** | `plugins/with-loopback-cleartext.js` (Android-only mods). `plugins/with-short-native-build-dir.js` (added 2026-11-05, T092) acts only when `os.name` contains "windows" or `READMATE_CXX_DIR` is set; on macOS it adds an inert block to the Android Gradle file |
| Import paths match file names (case) | **Pass on CI** | CI runs on Ubuntu (case-sensitive) for the SDK and Desktop. The Mobile web build is not in CI yet: `npm run build:web` on Ubuntu would catch a case mismatch in the WebView graph; not run |
| `app.json`: `ios.bundleIdentifier`, `ios.deploymentTarget` 18.2 | **Pass** | `com.anle.readmate`, `"deploymentTarget": "18.2"` |
| `/ios`, `/android` git-ignored, generated by prebuild | **Pass** | `reading-book-mobile/.gitignore` (`/android`; `/ios` never generated here). All native settings in `app.json` + plugins; `npx expo prebuild -p android` regenerated `android/` cleanly on 2026-11-05 |
| Native dependency records confirm iOS + Apple silicon | **Pass on paper** | `decisions/local-file-server.md` (in-repo module, Network.framework on iOS); `decisions/TEMPLATE.md`. No third-party native dependency was added without a record |
| In-repo native code lands for both platforms | **Pass, Swift untested** | `modules/local-server/ios/LocalServerModule.swift` (NWListener on `127.0.0.1`, Host check, GET only, `206` / `416`, token) beside the Kotlin side. Kotlin: 13 unit tests pass (`LoopbackServerTest.kt`, 2026-11-05). **Swift has never been compiled** (needs Xcode) |
| No Chromium-only behaviour in phone code | **Pass by review, with one iOS-specific gap** | `src/platform/long-press.ts` uses Pointer Events (WebKit supports them). The Mobile Reader does not depend on the `contextmenu` event: iOS WebKit does not fire it on a long press, so `useLiveSelection` offers "Mark selection" from the native selection on both platforms (T103) |
| Loopback transport configured on both | **Pass on paper** | iOS: `NSAppTransportSecurity.NSAllowsLocalNetworking`; Android: network security config allows cleartext to `127.0.0.1` only in release builds |
| Only relative paths stored; copy-to-cache picker | **Pass** | `file-service.ts` builds every path from a fixed folder + UUID; the DB stores `books/{id}/file`; `expo-host-fs.ts` uses `copyToCacheDirectory: true` and `Paths.document` |
| Early WebKit check | **Done at M2 (fake host, Playwright WebKit on Windows)** | `npm run feasibility:webkit`; not a substitute for iOS |

## Unproven on iOS until M6

| # | What | Why it matters | How M6 checks it |
|---|---|---|---|
| I1 | The Swift local server compiles and serves `Range` requests to WKWebView | All book bytes and the UI come through it | Build with Xcode; open each format; seek in a large PDF |
| I2 | WKWebView loads the UI from `http://127.0.0.1:{port}` with ATS `NSAllowsLocalNetworking` only | Without it the app shows nothing | First launch, networking off |
| I3 | pdf.js legacy build and its worker on Safari/WebKit 18.2 (module worker from the loopback origin) | PDF rendering | Open a PDF; turn 50 pages (also R5, memory) |
| I4 | epub.js iframes: selection, the "Mark selection" path and highlights inside the iframe on iOS | EPUB annotations (R1, R3) | Long press in an EPUB, mark, reopen |
| I5 | The iOS selection callout and the Mobile Reader's bottom selection bar do not overlap; the note sheet stays above the keyboard | R6 | Edit a note near the bottom of the screen |
| I6 | `localStorage` in WKWebView survives app restarts and updates (no 7-day eviction for the app's default data store) | Appearance and Library prefs | Change prefs, restart, update the build |
| I7 | `expo-sqlite` on iOS: JSON functions, `withExclusiveTransactionAsync` semantics | Stores and the write queue | Rerun T023 on iOS |
| I8 | `expo-document-picker` copies files from iCloud Drive / Files to the cache, with the right `name` and `size` | Import | Import from Files and from iCloud Drive |
| I9 | Safe areas: `viewport-fit=cover` (set in `web/index.html`) gives non-zero `env(safe-area-inset-*)` with the notch and home indicator | Bars and sheets placement | Visual check on a notched device |
| I10 | Lifecycle: background → flush event reaches the page before iOS suspends it | Reading position is saved | Read, press Home, kill, reopen |
| I11 | iOS 18.2 minimum: `Promise.try` / `Uint8Array.fromBase64` present (audit §14); nothing newer is used | Startup on the oldest supported iOS | Run on iOS 18.2 simulator or device |
| I12 | Text input in the WebView with the iOS keyboard (Settings fields, note sheet), and no zoom on focus (inputs are ≥ 16 px in the Mobile Reader sheets; other screens not audited) | Usability | Type in each field |
